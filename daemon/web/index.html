Endpoints

Every route this server answers. Request and response bodies below are the exact JSON shapes the server reads and writes.

GET /healthz

Liveness check. Returns 200 with the body ok once the daemon is up; nothing else calls out or touches a model.

curl

curl -s http://127.0.0.1:11500/healthz
GET /v1/models

Lists every model a request on this daemon can resolve: the cached cloud catalog plus whatever is installed on-device. No upstream call.

Response

{
  "object": "list",
  "data": [
    { "id": "<model-id>", "object": "model", "owned_by": "wally" }
  ]
}

curl

curl -s http://127.0.0.1:11500/v1/models
POST /v1/chat/completions

OpenAI-compatible chat completions. The server resolves model to a cloud or on-device endpoint and proxies the request there.

Request body

{
  "model": "<model-id>",
  "messages": [
    { "role": "user", "content": "hello" }
  ],
  "stream": false
}

Response

{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "choices": [
    { "index": 0, "message": { "role": "assistant", "content": "..." }, "finish_reason": "stop" }
  ],
  "usage": { "prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0 }
}
With "stream": true, the response is text/event-stream: a series of data: {...} chunk events, closed by data: [DONE].

curl

curl -s http://127.0.0.1:11500/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<model-id>",
    "messages": [{ "role": "user", "content": "hello" }]
  }'
POST /v1/completions

The legacy OpenAI text completion shape, for a tool that has not moved to chat completions. Same resolve-and-proxy path as chat completions.

Request body

{
  "model": "<model-id>",
  "prompt": "hello",
  "stream": false
}

Response

{
  "id": "cmpl-...",
  "object": "text_completion",
  "choices": [
    { "index": 0, "text": "...", "finish_reason": "stop" }
  ],
  "usage": { "prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0 }
}
With "stream": true, the response is text/event-stream chunks, the same shape as chat completions.

curl

curl -s http://127.0.0.1:11500/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<model-id>",
    "prompt": "hello"
  }'
POST /v1/embeddings

OpenAI-compatible embeddings. Resolves model the same way as the completion routes and proxies to that endpoint's embeddings path.

Request body

{
  "model": "<model-id>",
  "input": "hello"
}

Response

{
  "object": "list",
  "data": [
    { "object": "embedding", "index": 0, "embedding": [0.0, 0.0] }
  ],
  "model": "<model-id>",
  "usage": { "prompt_tokens": 0, "total_tokens": 0 }
}

curl

curl -s http://127.0.0.1:11500/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<model-id>",
    "input": "hello"
  }'
POST /v1/messages

Anthropic-shaped Messages. The server translates the request to OpenAI, proxies it to the resolved endpoint, then translates the response (or, for a stream, each event) back to Anthropic's shape.

Request body

{
  "model": "<model-id>",
  "max_tokens": 256,
  "messages": [
    { "role": "user", "content": "hello" }
  ],
  "stream": false
}

Response

{
  "id": "msg_...",
  "type": "message",
  "role": "assistant",
  "content": [{ "type": "text", "text": "..." }],
  "stop_reason": "end_turn",
  "usage": { "input_tokens": 0, "output_tokens": 0 }
}
With "stream": true, the response is text/event-stream: Anthropic's own event sequence (message_start, content_block_delta, ..., message_stop), translated chunk by chunk as the upstream streams.

curl

curl -s http://127.0.0.1:11500/v1/messages \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<model-id>",
    "max_tokens": 256,
    "messages": [{ "role": "user", "content": "hello" }]
  }'

Errors

A request for a model this daemon cannot resolve fails before any upstream call, in the error shape of whichever route you called.

OpenAI-shaped routes (chat completions, completions, embeddings, models)

{ "error": { "message": "...", "type": "wally_error" } }

/v1/messages

{ "type": "error", "error": { "type": "...", "message": "..." } }

Not signed in and no matching on-device model returns 401 with a hint to run wally login. A model that names an on-device engine this build has not linked in returns 501.

This page is served at GET /; its status panel reads GET /status. Neither carries a console URL or a credential, only the build channel and local counts.
